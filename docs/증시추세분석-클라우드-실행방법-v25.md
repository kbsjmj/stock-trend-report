# 증시추세분석(클라우드) 실행 방법

최종 갱신: 2026-11-01 (v23: 보고서 파일 이름 형식 변경, 지침 v23 1절)

※ 2026-11-01 기준 보고서 파일 이름은 `증시추세분석 (YYYYMMDD)-vN.pdf` / `.html`이다. 아래 예시 중 `_vN` 표기는 옛 형식이며 스크립트 수정 전까지 이름만 바꿔 쓴다.

## 1. 전체 흐름 한눈에 보기

매일 아침 두 가지가 자동으로 돕니다.

| 순서 | 누가 | 무엇을 | 언제 |
|---|---|---|---|
| ① | GitHub Actions (`daily-report.yml`) | 시세·지수 수집, 보고서 HTML·PDF 생성, Google Drive 업로드, 발행 기록 저장 | 매일 KST 07:00 (월~금) |

발행이 끝나면 카카오톡 "나와의 채팅"으로 한 줄 결과가 옵니다.

## 3. 자동 실행이 잘 됐는지 확인하기

1. GitHub에서 `kbsjmj/stock-trend-report` 저장소를 엽니다.
2. 위쪽 **Actions** 탭을 누릅니다.
3. `daily-report`를 누르면 날짜별 실행 기록이 보입니다. 초록색 체크면 성공입니다.
4. 성공하면 저장소의 `state/published/날짜_v1.json`에 발행 기록(Drive 링크 포함)이 생깁니다.

## 4. 보고서를 다시 발행하기

- **수동 실행:** Actions → `daily-report` → **Run workflow** → 날짜를 넣고 실행합니다. 같은 날짜가 이미 발행됐다면 `force` 옵션을 켜야 다시 발행됩니다.
- **원인 문장을 바꿔 발행:** `narrative/날짜.json` 파일을 고쳐서 저장소에 올리면(push) 자동으로 발행이 시작됩니다.

## 5. 1절 원인 문장 쓰는 법 (narrative)

파일 위치: 저장소의 `narrative/날짜.json` (예: `narrative/20261026.json`)

형식은 두 목록입니다. `us`는 1-1(미국), `kr`은 1-2(국내)입니다. 각 목록의 첫 줄은 개요(1~2줄), 나머지는 원인 항목입니다.

```json
{
  "us": [
    "개요 한두 줄 ...",
    "원인 1, 제목: 내용 (출처 매체)",
    "원인 2, 제목: 내용 (출처 매체)"
  ],
  "kr": [
    "개요 한두 줄 ...",
    "원인 1, 제목: 내용 (출처 매체)"
  ]
}
```

작성 규칙:
- 원인은 실제 기사에서 확인한 내용만 씁니다. 찾을 수 없으면 "확인 불가"라고 씁니다.
- 숫자는 `data/report_data_날짜.json`의 값과 맞춥니다.
- HTML 태그는 쓰지 않습니다.

## 6. 보고서 PDF 만들기와 로컬 저장

PDF는 HTML을 변환해서 만듭니다. 변환 스크립트는 `P1/소스/스크립트/render_report_pdf.py`입니다.

**준비 (한 번만):**
```
pip install playwright
playwright install chromium
```

**실행:**
```
python3 render_report_pdf.py "증시추세분석(20261027).html" 20261027 "/Users/KBS/kbsjmj/05-Project/04-증시추세분석(클라우드)"
```

- 결과 파일(새 형식): `증시추세분석 (20261027)-vN.pdf` (버전 번호는 같은 폴더의 최신 번호 + 1. 예: v1이 있으면 v2)
- 스크립트는 아직 `증시추세분석(20261027)_vN.PDF`로 저장합니다. 새 형식으로 쓰려면 저장 후 이름을 `증시추세분석 (20261027)-vN.pdf`로 바꿉니다. 스크립트 자체를 고치는 일은 승인 후에 합니다.
- 이미 있는 버전 파일은 덮어쓰지 않고 중단합니다. 번호를 직접 정하려면 `--version 3`을 붙이세요.
- HTML도 같은 번호로 저장합니다: `증시추세분석 (20261027)-vN.html`
- 확인할 것: 1쪽에 1절과 2절 "WTI는 …" 주석이 모두 있는지, 3·4·5·6·7절이 각각 새 쪽에서 시작하는지 봅니다.
- 화면용 HTML의 "▼ PDF 쪽 나눔" 점선 표시는 PDF에 나오지 않습니다.

현재 PDF는 9쪽입니다.

## 7. 차트 교체하기 (아직 미완료)

현재 차트 4개는 v1 보고서에서 옮긴 것이라 기준일이 **10/23**입니다. 10/26 기준 차트가 준비되면 다음 순서로 바꿉니다.

1. 60거래일 일봉 차트 4개(S&P 500, 나스닥 종합, 코스피, 코스닥)를 PNG로 준비합니다.
2. `P1/소스/보고서/증시추세분석(20261027)_소스.html`에서 `<img src="data:image/png;base64,...">` 부분을 새 이미지로 바꿉니다. 같은 자리에 있는 "10/23" 안내 문장도 지웁니다.
3. 위 6번 방법으로 PDF를 다시 만듭니다.

차트를 어떤 방식으로 만들지는 아직 정하지 않았습니다. 샌드박스와 Mac 모두 Yahoo·KRX 접속이 막혀 있어서, 데이터를 직접 주시거나 저장소의 차트 단계를 실행해야 합니다.

## 8. 시크릿(Secrets) 관리

위치: GitHub 저장소 → **Settings → Secrets and variables → Actions**

| 이름 | 용도 | 비고 |
|---|---|---|
| `KRX_ID`, `KRX_PW` | KRX 로그인 (pykrx) | 사용 중 |
| `GDRIVE_CREDENTIALS_JSON`, `GDRIVE_TOKEN_JSON` | Google Drive 인증 | 사용 중 |
| `GDRIVE_FOLDER_ID` | Drive 업로드 폴더 | 사용 중 |
| `KIWOOM_PAIRS` | (예전 키움 방식) | 코드에서 더 이상 쓰지 않음. 지워도 됩니다 |

- 값은 이 문서나 백업 폴더에 적지 않습니다.
- 값을 바꿀 때는 GitHub 웹 화면에서 직접 입력합니다.

## 11. 문제가 생겼을 때

| 증상 | 확인할 것 | 조치 |
|---|---|---|
| Actions가 빨간색 | 실행 로그의 빨간 단계 이름 | 해당 단계 로그를 열어 원인 확인. Secret 문제면 8번대로 값 재입력 |
| "narrative 파일 없음"으로 중단 | `narrative/날짜.json`이 저장소에 있는지 | 5번 형식으로 파일 작성 후 push |
| 이미 발행된 날짜인데 다시 돌리고 싶음 | 9번 수동 실행의 `force` | Run workflow에서 force 켜고 실행 |
| PDF가 9쪽이 아님 | 쪽 나눔 표시가 PDF에 나오는지 | 소스 HTML의 `class="newpage"`와 `@media print` 설정 확인 |
| PDF 변환 오류 | Playwright, Chromium 설치 여부 | 6번 준비 명령 다시 실행 |
| 카카오톡 미수신 | 예약 작업 실행 기록 | 9번의 중복 작업 정리 여부 결정 |
