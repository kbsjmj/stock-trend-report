이 절은 아래 모든 절보다 우선한다. 규칙은 지침 v33, 상태 기록은 컨텍스트 v33을 본다.

### A. 보고서 강제 재발행 (사용자 확인 후 한 번만)
1. 호출(REST, `gh workflow run`은 쓰지 않는다):
   ```
   curl -s -o /dev/null -w "%{http_code}\n" -X POST \
     -H "Authorization: Bearer $GITHUB_TOKEN" \
     -H "Accept: application/vnd.github+json" \
     -H "Content-Type: application/json" \
     https://api.github.com/repos/kbsjmj/stock-trend-report/actions/workflows/daily-report.yml/dispatches \
     -d '{"ref":"main","inputs":{"date":"20261030","write":"20261102","force":"true"}}'
   ```
   - 성공 응답은 `204`다. `Content-Type`을 빼면 `415`가 나온다.
2. 실행 상태 확인(약 3분 걸림, 30초 간격으로 확인):
   ```
   curl -s -H "Authorization: Bearer $GITHUB_TOKEN" -H "Accept: application/vnd.github+json" \
     "https://api.github.com/repos/kbsjmj/stock-trend-report/actions/workflows/daily-report.yml/runs?per_page=1"
   ```
   `status`가 `completed`, `conclusion`이 `success`일 때만 성공이다. 11/02 실행 `41376123046`은 약 3분 걸렸다.
3. 결과 확인: `state/published/20261030-w20261102_v{N}.json`의 `pdf_name`, `drive_file_id`, `webViewLink`를 읽는다.
4. 로컬 동기화: `git pull --rebase --autostash origin main`.

### B. 예약 작업 수동 실행과 결과 확인
- 실행: 예약 작업 도구로 해당 작업을 fire한다(사용자 요청이 있을 때만).
- 확인: 예약 목록에서 `last_run.status`가 `ROUTINE_RUN_STATUS_PENDING`이면 진행 중이다. `SUCCEEDED` 또는 실패 상태가 될 때까지 기다린 뒤 보고한다.
- 예약 작업이 "이미 발행됨"으로 끝나면 Mac 저장이 되지 않았다. 아래 C를 직접 한다.

### C. Mac 작업 폴더 저장 (수동)
1. 원본: 저장소 `reports/증시추세분석 (YYYYMMDD)_vN.pdf`(작성일, N은 state 버전). 주의: 저장소 파일명은 `_vN`(언더스코어)이고, Mac 저장 이름은 `-vN`(하이픈)이다.
2. 복사 이름: `증시추세분석 (작성일)-vN.pdf`. 예: `증시추세분석 (20261102)-v2.pdf`.
3. 같은 이름이 있으면 덮어쓰지 않는다. 중단하고 보고한다.
4. 복사 후 `cmp -s "원본" "사본" && echo same`으로 같은지 확인한다.

### D. 카카오톡 발송 전 점검
1. 글자 수: `python3 -c "import sys; print(len(sys.argv[1]))" "<문구>"`. 200자 이하여야 한다.
2. 발송 횟수: 같은 날 보낸 횟수를 세어 사용자에게 알린다. 2026-11-02는 3회다.
3. 링크: 발행 기록의 `webViewLink`를 쓴다.

### E. 맥 Python에서 구글 연결 확인 (사용자 터미널)
1. 인증서 묶음 설치: `python3 -m pip install --upgrade certifi`
2. 실행: `SSL_CERT_FILE=$(python3 -m certifi) python3 /Users/KBS/kbsjmj/.tmp_gmail_check/check_smtp_login.py`
3. 결과:
   - `SMTP 로그인: 성공`: 앱 비밀번호 정상
   - `인증 거부`: 앱 비밀번호를 새로 만들어 `.env`의 `GMAIL_APP_PASSWORD`에 넣는다(사용자 직접)
   - `CERTIFICATE_VERIFY_FAILED`가 그대로: `python3 -m certifi` 출력을 확인한다
4. 테스트 후 `/Users/KBS/kbsjmj/.tmp_gmail_check` 폴더를 사용자가 삭제한다.

### F. 샌드박스 제한
- `device_bash`는 맥이 아니라 Linux VM이다. 맥 전용 명령(`launchctl`, `open`)은 실행되지 않는다.
- 구글 주소 접속은 샌드박스에서 막힌다(`000` 응답). 구글 연결은 맥 쪽에서 확인한다.
- Terminal 앱은 computer use에서 클릭만 된다. 명령 입력은 우회하지 않는다.

## 5. 1절 원인 문장 쓰는 법 (narrative)

파일 위치: 저장소의 `narrative/날짜.json` (예: `narrative/20261026.json`)

형식은 두 목록입니다. `us`는 1-1(미국), `kr`은 1-2(국내)입니다. 각 목록의 첫 줄은 개요(1~2줄), 나머지는 원인 항목입니다.

```json
{
  "us": [
    "개요 한두 줄 ...",
    "원인 1, 제목: 내용 (출처 매체)",
    "원인 2, 제목: 내용 (출처 매체)"
  ],
  "kr": [
    "개요 한두 줄 ...",
    "원인 1, 제목: 내용 (출처 매체)"
  ]
}
```

작성 규칙:
- 원인은 실제 기사에서 확인한 내용만 씁니다. 찾을 수 없으면 "확인 불가"라고 씁니다.
- 숫자는 `data/report_data_날짜.json`의 값과 맞춥니다.
- HTML 태그는 쓰지 않습니다.

## 6. 보고서 PDF 만들기와 로컬 저장

PDF는 HTML을 변환해서 만듭니다. 변환 스크립트는 `P1/소스/스크립트/render_report_pdf.py`입니다.

**준비 (한 번만):**
```
pip install playwright
playwright install chromium
```

**실행:**
```
python3 render_report_pdf.py "증시추세분석(20261027).html" 20261027 "/Users/KBS/kbsjmj/05-Project/04-증시추세분석(클라우드)"
```

- 결과 파일(새 형식): `증시추세분석 (20261027)-vN.pdf` (버전 번호는 같은 폴더의 최신 번호 + 1. 예: v1이 있으면 v2)
- 스크립트는 아직 `증시추세분석(20261027)_vN.PDF`로 저장합니다. 새 형식으로 쓰려면 저장 후 이름을 `증시추세분석 (20261027)-vN.pdf`로 바꿉니다. 스크립트 자체를 고치는 일은 승인 후에 합니다.
- 이미 있는 버전 파일은 덮어쓰지 않고 중단합니다. 번호를 직접 정하려면 `--version 3`을 붙이세요.
- HTML도 같은 번호로 저장합니다: `증시추세분석 (20261027)-vN.html`
- 확인할 것: 1쪽에 1절과 2절 "WTI는 …" 주석이 모두 있는지, 3·4·5·6·7절이 각각 새 쪽에서 시작하는지 봅니다.
- 화면용 HTML의 "▼ PDF 쪽 나눔" 점선 표시는 PDF에 나오지 않습니다.

현재 PDF는 9쪽입니다.

## 11. 문제가 생겼을 때

| 증상 | 확인할 것 | 조치 |
|---|---|---|
| Actions가 빨간색 | 실행 로그의 빨간 단계 이름 | 해당 단계 로그를 열어 원인 확인. Secret 문제면 8번대로 값 재입력 |

| PDF가 9쪽이 아님 | 쪽 나눔 표시가 PDF에 나오는지 | 소스 HTML의 `class="newpage"`와 `@media print` 설정 확인 |
| PDF 변환 오류 | Playwright, Chromium 설치 여부 | 6번 준비 명령 다시 실행 |
| 카카오톡 미수신 | 예약 작업 실행 기록 | 9번의 중복 작업 정리 여부 결정 |
