[원칙] 판단은 코드가 한다. 매 단계 앞에 아래 도구를 실행하고, 출력의 state 가 말하는 일만 한다.
  cd 저장소 && git pull --rebase origin main && python3 scripts/routine_state.py
출력은 JSON 한 줄이다(state, key, date, write, next_action, data_reason, kakao_message 등). 날짜·키를 직접 계산하지 않는다.

0. 준비: /tmp/work 아래에 git clone https://github.com/kbsjmj/stock-trend-report 후 cd. 이미 있으면 git pull --rebase origin main. 원격이 kbsjmj/stock-trend-report 가 아니면 중단. 인증 실패면 실패 알림(아래 F)으로 간다.

반복(최대 6회): 위 도구를 실행해 state 를 읽고 다음처럼 한다.
- TOO_EARLY: 안내된 시각까지 sleep 으로 기다린 뒤 다시 실행한다(최대 10분). 그래도 TOO_EARLY 면 F로 간다.
- DONE: 아무것도 보내지 않고 7로 간다.
- NEED_DATA: 데이터만 만드는 실행을 한다. 반드시 date 입력만 전달한다(write, force 금지). narrative 가 없을 때만 한다(도구가 보장한다).
    gh api -X POST repos/kbsjmj/stock-trend-report/actions/workflows/daily-report.yml/dispatches -f ref=main -f "inputs[date]=DATE"
  gh 가 없거나 403 이면 환경변수 GITHUB_TOKEN 이 있을 때 curl -X POST -H "Authorization: Bearer $GITHUB_TOKEN" -H "Accept: application/vnd.github+json" 같은 주소에 {"ref":"main","inputs":{"date":"DATE"}} 를 보낸다(토큰 값은 출력하지 않는다). 둘 다 안 되면 F로 간다.
  실행 후 gh api "repos/kbsjmj/stock-trend-report/actions/runs?per_page=5" 로 방금 만든 workflow_dispatch 실행이 completed 될 때까지 30초마다 확인한다(최대 25분). 이미 진행 중인 실행이 있으면 새로 만들지 말고 그 실행이 끝나기를 기다린다. 끝나면 pull 하고 다시 도구를 실행한다. 결론이 failure 면 F로 간다.
- NEED_NARRATIVE: 4단계로 narrative 를 쓰고 push 한 뒤 다시 도구를 실행한다.
- WAIT_PUBLISH: 60초마다 pull 하고 도구를 실행한다(최대 30분). 발행 기록이 생기면 계속한다. 30분이 지나면 F로 간다.
- NEED_KAKAO: 6단계로 간다.
- STALE_NARRATIVE: 자동 처리하지 않는다. F로 간다.

4. narrative 작성 (state 가 NEED_NARRATIVE 일 때만)
  - 입력: data/report_data_DATE.json. 숫자는 이 파일 값과 정확히 같아야 한다. 형식은 narrative/20261112.json 을 본다: {"us": [...], "kr": [...]}, HTML 태그 금지.
  - 기사 검색은 서로 다른 검색어로 4회 이상, 매체 3곳 이상. 기사 날짜가 기준일(date)과 맞는지 본다. 요인 항목마다 끝에 (매체명)을 괄호로 붙인다.
  - 기사 원문을 열지 못했으면 ※ 항목에 "원문 열람은 확인하지 못했다"고 쓴다.
  - 매체마다 수치가 다르면(예: 외국인 수급) 본문에 그 수치를 쓰지 않고 ※ 항목에 차이를 적는다.
  - 기준일 시장을 설명하는 기사를 찾지 못한 요인은 '(출처 미확보, 지수 흐름 기준)'으로 쓴다. 추측으로 원인을 지어내지 않는다.
  - 저장 후: git add narrative/KEY.json; git -c user.name=kbsjmj -c user.email=101155105+kbsjmj@users.noreply.github.com commit -m "narrative: DATE 기준 1절 원인 문구 (작성 WRITE)"; git push origin HEAD:main. push 가 실패하면 add_repo 도구가 있으면 owner=kbsjmj, repo=stock-trend-report, access=push 로 호출하고 한 번 더 시도한다. 이 push 가 발행을 자동으로 시작한다.

6. 카톡 1회 (state 가 NEED_KAKAO 일 때만)
  - 도구 출력의 kakao_message 를 그대로 쓴다(수정 금지). 길이 200자 이하인지 확인한다.
  - PlayMCP 의 KakaotalkChat-MemoChat 도구(도구 이름이 안 보이면 ToolSearch 로 "KakaotalkChat" 를 찾는다)로 한 번만 보낸다.
  - 성공 응답을 받으면: python3 scripts/kakao_message.py record --key KEY --write WRITE --version VER --link LINK (VER, LINK 는 도구 출력의 published_version, published_link). 그다음 git add state/kakao; commit -m "kakao log: WRITE 작성 (기준 DATE v VER) 전송 기록"; git push origin HEAD:main. push 실패는 "전송 완료, 기록 미완료"로 따로 보고한다.
  - 전송이 실패하면 다시 보내지 않고 F로 간다.

7. 결과 보고(마지막 출력): 한 줄 요약 / 단계별 결과(KEY, 거친 state 순서, 데이터 생성 시각, narrative 커밋, 발행 버전, 카톡 전송 여부와 기록 파일) / 전송한 문구 전문. 실패는 실패라고 쓴다.

F. 실패 알림: 어느 단계에서 왜 멈췄는지 한 줄로 정리해 카톡 1회를 보낸다(100자 이내, 예: "[증시추세분석 예약 실패] 단계=NEED_DATA, 사유=워크플로 실행 권한 없음"). 이 알림은 state/kakao 에 기록하지 않는다. 같은 실행에서 두 번 보내지 않는다. 그다음 7로 간다.

금지: 장중·마감 전 데이터로 narrative 작성, write/force 입력으로 dispatch, 기존 narrative·state·kakao 파일 덮어쓰기와 삭제, Drive 파일 삭제·공유 변경, GitHub Secrets 변경, 키·토큰 값 출력, HTML 생성, 이 예약 작업 자신의 설정 변경. 이미 보낸 카톡은 다시 보내지 않는다.
